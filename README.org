#+TITLE: MIDI bridge daemon
#+AUTHOR: 8dcc

Turn a simple input device, like a rotary knob, into a MIDI controller for any
program that supports MIDI learn.

The daemon reads the device through evdev and turns its input into absolute MIDI
Control Change messages on a virtual MIDI port. One physical knob drives several
"virtual knobs" (CC 20 to 27): turning it while pushed switches between them,
and a single push toggles the current knob between a fine and a coarse step.

Device support is abstracted behind a small device interface. The first
supported device is the Anticater, a rotary knob that the kernel sees as a
keyboard, over USB or Bluetooth.

The project has two programs:

- *Daemon*: always running (as a systemd user service). It waits for the device,
  owns all state and settings, and sends the MIDI.
- *GUI*: an optional Qt window that shows the active knob and the values, and lets
  you change the settings. It talks only to the daemon, over a Unix socket; you
  can close it and the device keeps working.

The daemon and the GUI never import each other; they only share
=midi_bridge_common=. The socket protocol is the only contract between them.

The device, the controller, the MIDI output and the IPC server don't know about
each other. Each one gets its callbacks when it is created, and =app= connects
them. The controller reports knob value changes (sent as MIDI) separately from
any state change (broadcast to the GUIs).

* Installing

Install the dependencies: =evdev=, =mido=, =python-rtmidi= and =PySide6=. For example,
on Arch Linux:

#+begin_src sh
sudo pacman -S python-evdev python-mido python-rtmidi pyside6
#+end_src

The daemon reads the device from =/dev/input=, so your user needs access to it. On
most distributions, that means being in the =input= group:

#+begin_src sh
sudo usermod -aG input "$USER"   # then log in again
#+end_src

Then install and start the daemon (nothing goes outside your home directory):

#+begin_src sh
./install.sh
systemctl --user enable --now midi-bridge-daemon
#+end_src

The daemon grabs the device, so its input no longer reaches the rest of the
system. For the same reason, no other program may be grabbing it (through evdev
or otherwise) while the daemon runs.

You can also run both programs straight from the repository with
=python3 -m midi_bridge_daemon= and =python3 -m midi_bridge_gui=.

* Usage

The daemon creates a MIDI port called =midi-bridge=. Connect it to your program
like any other MIDI controller (in the program's MIDI settings, or with =qpwgraph=
or =aconnect=), then map the knobs with the program's MIDI learn.

The controls of a push-and-turn knob are:

| Action           | Effect                                           |
|------------------+--------------------------------------------------|
| Turn             | Change the active knob's value                   |
| Push, then turn  | Switch to the next or previous knob              |
| Push and release | Toggle the active knob between fine and coarse   |

Each knob has its own step size ("sensitivity") and its own fine and coarse
values. A push switches the sensitivity to whichever of fine and coarse is
further from the current one. You can change all three in the GUI:

#+begin_src sh
midi-bridge-gui
#+end_src

Edits are sent when you press Enter, leave the field, or click the arrows.

The daemon logs a warning at startup if a knob uses a CC number that is reserved
or has a conventional meaning in MIDI (mod wheel, volume, sustain, and so
on). See its log with =journalctl --user -u midi-bridge-daemon=.

* Socket protocol

The daemon listens on =$XDG_RUNTIME_DIR/midi-bridge-daemon.sock= (or
=/tmp/midi-bridge-daemon-<uid>.sock= if that variable is unset). Messages are JSON
objects, one per line.

When a client connects, and after every change, the daemon sends the full state:

#+begin_src json
{"type": "state", "device_connected": true, "selected_knob": 2,
 "knobs": [{"cc": 20, "value": 64, "sensitivity": 1, "fine": 1, "coarse": 8},
           ...]}
#+end_src

A client changes a knob's settings with any subset of =sensitivity=, =fine= and
=coarse= (integers from 1 to 127):

#+begin_src json
{"type": "set_knob", "knob": 3, "settings": {"sensitivity": 5}}
#+end_src

If the request succeeds, every client gets the new state, including the one
that sent it; that is its confirmation. If it is invalid, only that client gets
an error back, and nothing changes:

#+begin_src json
{"type": "error", "message": "coarse must be in 1..127"}
#+end_src

To poke at it by hand:

#+begin_src sh
socat - UNIX-CONNECT:"$XDG_RUNTIME_DIR/midi-bridge-daemon.sock"
#+end_src
